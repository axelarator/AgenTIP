OVERVIEW

One report, two paths out

Everything downstream of ingestion splits along one line: lookups that any visitor could make run automatically, and traffic an attentive operator would notice runs only when asked. That split is the colour code below, and it holds through every diagram on this page.

automatic — passive lookups + light live checks on explicit ask — crafted or loud traffic queued, not yet run
STAGE 01

Ingesting the report

ingest_report(source, cluster_name=None) fetches a URL or local file, strips HTML, runs PDFs through pdftotext when poppler is present, then re-fangs the text in memory — hxxp, [.], [at] — so the regexes can match.

Extraction pulls hashes, domains (TLD allowlist), IPs (private and reserved dropped), URLs, emails, CVEs, wallets and T1234.005 technique IDs. It also pairs ports to IPs two ways: direct 1.2.3.4:886 adjacency, and prose like "TCP port 886 (IPs: …)" within one sentence-sized chunk — so a later probe hits the real C2 port instead of defaulting to 443.

The cluster name comes from the argument, or from a vendor-naming heuristic that raises on zero or multiple candidates rather than filing a report under the wrong actor.

tracked always

Every extracted value is filed

Dedup is by value: a repeat just appends the new source to that observable's provenance and bumps last_seen. A domain's live certificate SHA256 is auto-filed alongside as cert-sha256:… with hash_kind: certificate, so it is pivotable from the moment the domain is tracked.

queued selectively

Only probe-worthy values reach the queue

Extraction is a blind regex — it will match a version string, a public resolver, or a vendor's own site. _is_probe_worthy drops private, reserved, loopback and link-local addresses, all IPv6 (the probe VM has no v6 route), known resolvers and vendor/sinkhole domains. Each skip is recorded with its reason and can be forced back with requeue_fingerprint.

STAGE 03

Pivoting and probing are different operations

pivot — run it without being asked

Three entry points

  • pivot_observable — display only, writes nothing anywhere.
  • pivot_and_expand — files subdomain siblings; hosted domains only with include_cohosted=True; kit-fingerprint siblings go to review, never auto-filed.
  • pivot_cluster — sweeps every tracked value, stamps lifecycle + snapshot back, and writes the dated history row.
probe — only on an explicit ask

Two tools

  • probe_pending_fingerprints.py — drains the queue, probes every port the report recorded, dispatches all targets concurrently over one ControlMaster connection, then reads JA4+/JARM back out of OpenSearch.
  • active_scan — nmap top-100 -sV plus dirsearch with 404-baseline suppression and recursive open-directory listing. Blocks up to 900s.

The fingerprint drain avoids cross-host clock comparison entirely: it snapshots the newest ts already indexed in OpenSearch before the batch fires, then accepts only documents newer than that. Every timestamp compared is stamped by Zeek's own clock — which is what actually caused the original bug, so a fixed window would not have been a fix. Each active_scan is audited in active_scans with its Zeek window, so the packets stay findable in Arkime afterwards.

STAGE 04

The time-series layer

The cluster JSON answers who and what. DuckDB at data/tracking/tracking.duckdb answers when — one dated observation row per indicator per source, linked back only by actors.cluster_slug. Eight tables: observations, asn_changes, attribute_changes, actors, correlations, opendir_files, active_scans, zeek_matches.

Change detectors, day over day

certificate cert sha256 http title / server webamon kit fingerprint subdomains infostealer count PTR resolved IPs hosted domains ASN / netname open ports open-dir files

The two amber ones move only when someone runs an active scan; everything else moves on the automatic sweep. A change detected against a baseline older than 90 days is recorded at lower confidence, and a first sighting is written as first_seen — a baseline, not an event, so a seeding day can't wake the agent.

STAGE 05

The daily loop

Deliberately outside this loop: nmap and dirsearch (loud), and the Zeek/OpenSearch cross-reference — those indices only hold data when the VM originated traffic, so a daily check would mostly find nothing and add noise. Run opensearch_xref.run_daily_xref by hand after a probe or detonation session. Digests and logs are pruned at 180 days.

RECENTLY CORRECTED

Three failures worth remembering

Each of these was silent — the pipeline kept reporting confidently while the answer was wrong. That shape is the reason they're listed here rather than left in the log.

cc9adb0

Infostealer hits that named nothing

symptom → 12 JadeProx domains flagged as compromised; every one reporting exactly 25 hits

An unquoted username:@<term> clause was token-analyzed by the index and OR'd into most of the corpus — a nonsense domain returned 572,358 "hits" on aarp.org and netflix.com. The reported count was len(results), i.e. the page size, which is why everything read 25. Both clauses are now phrase-quoted and every row is re-checked against the term client-side; total_hits is the matched count, with raw_total_hits and capped alongside. False rows were purged from the store and the poisoned entries from the pivot cache.

e305704

A cached failure served as the answer

symptom → every sweep returning status "unknown", asn null, no error anywhere to explain it

The cache gate skipped only a top-level error key, but ripestat_lookup reports per-sub-call <name>_error keys so a partial answer still comes back. A run where every RIPEstat call failed cached {"network_info_error": …} as the result for the whole TTL. Seen live after the MCP server started without CTI_PROBE_* set — it passed the literal ${CTI_PROBE_HOST} through to ssh.

98ddc7b

Suppression that never fired

symptom → 50 AWS co-tenant domains stamped onto each of two tracked Fox Tempest IPs

RIPEstat returns an ASN as a string — "16509" — while SHARED_HOSTING_ASNS holds ints, so the membership test never matched and shared-hosting suppression silently did nothing. Every existing test stubbed the ASN as an int, so they all passed. _asn_int now normalizes "16509", "AS16509" and list forms at both sites. The same commit made the suite hermetic — sockets blocked, probe transport blocked, API keys unset — so an unstubbed path fails loudly instead of quietly SSHing to the lab. Runtime 86s → 10s.
